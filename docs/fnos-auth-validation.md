## 独立 Agent 场景演练

Agent 仅从技能入口和关联资料读取规则，未获得预期答案；场景结果返回后按预期逐项核对。

- A：Android 桥就绪、原始 null、有宿主 Cookie 来源证据和有效材料 → 允许 Cookie 兼容，报告格式可用，业务授权保持未验证。
- B：原始字符串 `"null"` → 响应不可识别，不读取 Cookie 兜底。
- C：原生 Promise 拒绝且 Cookie 存在 → 固定拒绝诊断，不兜底。
- D：原生材料有效但未提供 token，Cookie 中另有 token → 整组使用原生材料，不拼接 token。
- E：原始 null，但未建立宿主 Cookie 来源证据 → 不读取 Cookie，报告原生空返回，不将 Cookie 误报为缺失。
- F：原生调用超时，随后取消且凭据迟到 → 丢弃迟到结果，不继续业务请求。终态先后规则经补充后单独复核。
- G：iOS 截图仅显示权限错误，未知端点和 HTTP 状态 → 获取脱敏阶段及状态，保持根因未知，不直接改变相册 ACL。
- H：服务端请求官方平台配置能力 → 选择服务端应用 token 和 Unix Socket；缺少业务 schema 时查官方定义，不虚构调用参数。
- I：手机缺桥，提议尝试旧网页 secret → 停止手机会话路径，不读取旧 localStorage 绕过缺桥。
- J：来源仓库只读且有未提交改动，仅授权独立仓库提炼 → 保持来源只读，将产出限定到授权目标仓库。

F 的针对性复核：超时先发生则保留 `FNS_HANDLER_TIMEOUT`；取消先发生则保留取消结果，可省略会话失败阶段。两种时序均省略尚未取得的会话来源，不发依赖请求，忽略后续事件和凭据。

## 已修正的问题

1. 尚未取得会话时省略会话来源；Cookie 未尝试或没有来源证据时省略状态，避免假报 `missing`。
2. 历史设备反馈补充脱敏记录摘要和提交标识，明确未重新执行来源项目测试，也不代表所有边界已有测试覆盖。
3. 明确首次终态生效和未知/不适用阶段的省略规则，消除取消与超时的结果竞争歧义。
4. npm 归档 README 中 Desktop 凭据能力仍标为候选；技能已标注此矛盾，不能将包可下载当作宿主能力已稳定可用。
