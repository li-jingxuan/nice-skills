# 技能编写约定

## 目录与命名

- 每个正式技能放在 `skills/<skill-name>/`。
- 技能目录与 frontmatter 的 `name` 保持一致，使用小写字母、数字及短横线。
- 每个技能必须包含 `SKILL.md`；其余目录按需添加。
- 技能应尽量独立，不依赖开发者机器上的绝对路径。

## SKILL.md

文件以 YAML frontmatter 开头，至少包含：

```yaml
---
name: your-skill-name
description: 描述技能能完成什么，以及用户提出哪些需求时应使用它。
---
```

正文写清目标、所需输入、操作步骤、输出要求与验收标准。步骤应能指导 Agent 实际执行，避免只写原则或口号。

`description` 应帮助 Agent 判断何时使用技能。将必要约束写入正文，较长的背景资料放入 `references/`，并注明具体文件和读取时机。

## 配套文件

- `scripts/`：适合重复执行或需要确定性结果的脚本，注明依赖、参数与运行方式。
- `references/`：规范、示例、接口文档等参考材料。
- `assets/`：用于产出的静态资源、文件模板等。

路径以技能目录为基准，引用具体文件，避免要求 Agent 无差别读取全部资料。不要提交凭据、缓存或依赖安装目录。

## 提交前检查

- 名称与描述完整，模板占位内容已替换。
- 文件引用有效，命令和脚本可在声明的环境中运行。
- 使用至少一个典型需求验证技能的触发、执行与输出。
- 对外部写入、覆盖文件等操作说明边界，并遵守用户及目标平台的授权规则。
