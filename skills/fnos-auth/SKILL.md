# 飞牛认证与当前用户会话

## 目标与范围

为 fnOS Web 应用选择正确的认证路径，实现或排查当前用户会话，提供可复核的诊断与验证记录。

优先使用目标系统支持的官方能力。手机桥、可读 Cookie 和相册上传属于不同层面的能力，不能视为所有飞牛版本都支持的统一登录协议。本技能提供实施流程和兼容边界，不附带任何 NAS 凭据或业务相册配置。

## 输入

- 目标代码或待分析的脱敏现象，以及用户允许修改的范围。
- 能从现有配置取得的 fnOS、App、SDK 版本，访问方式（统一网关、独立浏览器、手机 App），页面是否处于 iframe。
- 目标操作：调用官方后端 API、取得当前用户上传凭据，或排查业务接口授权。

先从仓库、manifest、依赖锁文件和已有脱敏记录获取信息，仅在关键输入无法取得时询问用户。不要求用户粘贴 Cookie、密码、token、secret、原始桥响应或完整 HAR。

## 执行流程

### 1. 确认修改范围并选择认证路径

1. 检查目标仓库说明和已有变更，保留用户的未提交工作；用户要求只读时仅分析。
2. 区分以下路径，按需阅读 [运行环境与会话规则](references/runtime-and-session.md)：
   - 官方后端 API：应用进程使用系统注入的 `TRIM_API_TOKEN`，经 Unix Socket 调用官方接口；该 token 不能放入前端。
   - Desktop SDK 会话能力：先确认方法适用环境和能力授权；不能把 Desktop 专用方法当作手机方案。
   - 手机 App 内嵌页面：确认原生桥、就绪条件及宿主实际返回结构。
   - NAS 网页宿主：只在已观察到宿主提供的前提下使用可读会话材料；独立浏览器不能默认继承宿主存储。
3. 使用 JS SDK 时核对 `manifest` 的 `micro_app=true` 和功能所需 scope。安装元数据是否生效须单独验证，改前端镜像不能证明宿主配置已更新。
4. SDK 环境属性和注入能力用于选择路径；UA 仅供兼容识别与脱敏平台分类，不能证明身份、权限或宿主可信。

### 2. 建立最小证据链

按“官方文档 → 锁定版本 SDK 发布包 → 目标 NAS 自带前端 → 目标设备实测”核对。阅读 [来源与验证](references/evidence-and-validation.md)，记录版本、证据类别和未确认项。

SDK 未定义的字段不可写成官方契约。`getUserMessage` 的会话字段映射、同源父页面桥和 Cookie 兜底均需按兼容实现说明。新版本出现已文档化的替代接口时，重新评估，不沿用旧假设。

### 3. 实现或审查会话获取

将会话获取集中为一个模块，让业务代码只接收经校验的临时凭据；每次操作重新读取，不缓存到持久存储。

手机流程按顺序处理：

1. 仅检查当前页面和可验证同源的直接父页面；记住各自的一次性就绪事件，不将一个窗口的就绪状态用于另一个窗口。
2. 支持延迟注入；按已核对的 SDK 版本判断就绪。初始化与调用共享有限超时，支持取消并清理监听器、计时器和轮询。
3. 每次获取最多调用一次 `flutter_inappwebview.callHandler("getUserMessage")`；同步抛错、拒绝、超时、空返回和格式错误分开处理。
4. 在限长、限层的解析中接受已确认的 JSON envelope；校验 secret 和可选 token。不能为修复错误而猜测 handler 或遍历字段寻找“像凭据”的值。
5. 有效原生会话优先，整组使用，不拼接其他来源的 token。
6. 若目标环境有 Cookie 来源证据，仅在桥**原始返回** `null` 或 `undefined` 时尝试可读 `fnos-Secret` 和可选 `fnos-token`。拒绝、超时、非空错误、字符串 `"null"`、字段不识别、缺桥或未就绪均不触发此兜底；手机不回退到 localStorage。
7. 有效格式只代表材料可用于后续请求，不证明账号一致、会话新鲜或业务权限通过。无法取得会话时输出脱敏原因并停止相关业务请求。

详细解析、Cookie 校验、网页兼容和取消边界见 [运行环境与会话规则](references/runtime-and-session.md)。

### 4. 将认证绑定到正确的请求

- 当前用户的内部 NAS 请求使用当前页面 origin 和固定、审核过的接口路径，显式设置 `credentials: "same-origin"`；拒绝意外重定向，不向任意配置地址发送凭据。
- HttpOnly 登录 Cookie 由浏览器携带，页面不读取、不复制到后端。统一网关可能过滤系统 Cookie，不能假定应用后端收到当前用户 NAS 会话。
- 上传 secret 只在前端内存中用于目标协议要求的签名；上传 token 仅发送到已确认的同源上传端点。不发给业务后端、日志、遥测或错误上报。
- 官方后端 API 的应用 token 按官方调用方式使用，不能代替当前用户的相册凭据或跳过用户授权。
- 后续操作固定使用同一来源；写请求失败不自动重放。诊断复用本次会话获取的安全元数据，不额外调用桥。

### 5. 提供可复制的脱敏诊断

按 [诊断与排障](references/diagnostics.md) 使用固定字段和枚举。至少区分：桥不存在、未就绪、调用超时、调用拒绝、原生空返回且 Cookie 不可用、非空响应不可识别、会话格式可用、下游 HTTP 或业务拒绝。

同时记录失败操作阶段、HTTP 状态与已确认的业务码，阶段变化时清除上次请求状态。不得用“会话检查通过”替代“上传/业务授权通过”，也不得把所有 403 都解释为目标资源 ACL。

### 6. 完成验证与交付

按 [来源与验证](references/evidence-and-validation.md) 选择与改动相应的检查：解析与异步边界、秘密不外泄、同源请求，以及实际目标设备的授权验证。

诊断检查应尽量只获取会话并立即丢弃凭据。需要上传、创建分享或改变部署时，遵循本次任务已授权的范围，不为检查认证调用付费业务或修改用户权限。

## 输出要求

- 给出修改或分析结果、适用环境与版本、采取的认证路径和文件位置。
- 说明证据属于官方契约、实现观察、模拟验证还是设备实测；未确定的原因保持未确定。
- 汇报测试和实机覆盖，提供不含凭据的诊断摘要；若只验证会话，明确业务授权尚未验证。
- 只有用户要求安装技能、提交、推送或部署时才执行相应交付，不将整理技能扩展为修改来源项目。
