# 诊断与排障

## 诊断结构

使用固定白名单构造新的诊断对象，禁止复制桥返回、异常对象、请求或响应对象后再删敏感字段。保留以下信息即可：

- 固定诊断版本与发布构建标记。
- 平台类别 `android | apple | other`，从 UA 提取的受限数字 App 版本或 `unknown`，不输出完整 UA。
- 框架类别 `top | same-origin-frame | cross-origin-frame`。
- 桥位置 `none | current | same-origin-parent`、就绪事件是否观察到、`_platformReady` 是否严格为 true。
- 固定阶段、会话来源 `native | cookie | browser-storage`。
- Cookie 状态 `missing | invalid | blocked | available`；`available` 仅指格式可用。
- 下游固定操作名、HTTP 状态和已确认字段中的整数业务码；如需检查签名时效，可记录合法响应 Date 相对客户端的秒差。

不包含原始返回、错误文本、用户标识、资源 ID、NAS 地址、文件路径、完整 URL、Cookie、secret、token、签名、凭据哈希或凭据片段。业务确需资源定位时，由业务自行评估单独的诊断字段；通用认证诊断不默认收集。

字段形状仅在不可识别的非空响应中按需输出：固定白名单字段名加类型，未知 key 一律改成 `unknown`；例如最多 8 个字段、深度 2。未知 key 本身也可能是秘密。字符串只输出 `string`，不解析其中任意未知内容，不使用 `JSON.stringify(raw)` 生成诊断。

业务码仅从接口确认过的字段读取，例如 `code`、`errno` 或 `errorCode`，且必须是安全整数。不要为“收集更多信息”遍历服务器返回并记录所有数字字段。

## 会话阶段及处理

- `FNS_NO_BRIDGE`：检查是否从正确宿主打开、微应用声明及安装元数据是否生效；仅缺桥不能推断登录失效。
- `FNS_NOT_READY`：桥存在但就绪条件未满足；检查早发事件、事件归属和延迟注入。不要直接删掉就绪检查。
- `FNS_HANDLER_TIMEOUT`：调用已开始但未在时限内完成；停止后续请求，清理等待，忽略迟到结果。
- `FNS_HANDLER_REJECTED`：同步抛错或 Promise 拒绝；显示固定说明，不输出原生错误文本，不触发 Cookie 兜底。
- `FNS_NATIVE_EMPTY`：原生原始空值，Cookie 兼容未取得材料；附固定 Cookie 状态，不能靠猜字段名修复。
- `FNS_RESPONSE_UNRECOGNIZED`：非空结果解析或字段校验失败；提供限长字段形状，不尝试旧存储或备用账号。
- `FNS_WEB_STORAGE_BLOCKED`、`FNS_WEB_SECRET_MISSING`、`FNS_WEB_SESSION_INVALID`：分别提示网页宿主存储受限、未提供材料或格式无效。
- `FNS_READY`：已取得格式有效材料；此阶段不表示服务器认证或业务 ACL 已通过。
- 取消：按取消结果处理，不包装为登录失败，不触发自动重试。

阶段名是兼容实现的诊断约定，非 fnOS 官方错误码。业务可采用不同名称，但需保持语义稳定。

## 下游失败定位

进入每个请求步骤时，重置上次 HTTP 状态、业务码、字段和时钟差。操作名使用固定枚举，例如 `upload-path`、`upload`、`album-notice`、`share-create`、`share-detail`，不输出完整请求 URL。

HTTP 错误与 HTTP 200 中的 JSON 业务码分别记录；HTTP 200 空响应可能是接口成功约定，不能一律要求 JSON。响应格式和成功规则应按目标端点定义。

- HTTP 或已确认语义的业务 401：引导重新登录后重试，不能静默更换凭据来源。
- HTTP 403：先识别哪个端点拒绝，检查当前账号、目录或资源授权。
- HTTP 200 + 业务 403：记录失败步骤，不笼统解释为目标相册 ACL；查询目录、传输、入库和分享可能各有授权要求。
- 某 NAS 相册版本曾对无效 `authx` 返回 HTTP 200 + 业务 5000；这仅是该版本的观察，不能作为 fnOS 全局错误码规范。
- 有效材料后仍失败：分别检查浏览器登录会话、上传凭据、目标权限、请求编码及签名；“可能身份不一致”只是待验证原因。
- 有明显时钟差：作为时效排查线索，不自动改系统时间或重写服务签名规则。

不要将 `/app/token` 当作 secret 获取接口：历史观察中它成功返回 HTTP 200 空体，只验证会话。`getAppMessage()` 的 appApi 信息也不证明已经提供用户凭据。

## 用户反馈与验证入口

提供可选中、可复制的诊断文本；剪贴板失败时保留手动复制入口。报告不包含秘密，因此不要求用户收集控制台原始输出或完整网络抓包。

“检查会话”只获取并丢弃材料，不发起上传或分享。若需要验证业务授权，按任务授权进行独立步骤，使用小型本地测试文件，避免调用付费内容生成。错误时保留原文件，不自动重放可能已成功的上传/创建分享。

若诊断字段本身可能接收外部内容，应再次白名单投影并设置长度上限；复制诊断的实现也要验证不会回显秘密。
