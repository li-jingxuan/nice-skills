# 来源与验证

## 可公开复核的依据

1. [飞牛开放平台：调用方式](https://developer.fnnas.com/api/calling/)：`micro_app=true`、SDK 环境属性、scope、官方后端 Unix Socket 接口与 `TRIM_API_TOKEN`。网页内容可能更新；实施时重新核对目标系统支持程度，不能把当前文档能力直接套用到旧系统。
2. [SDK npm 页面](https://www.npmjs.com/package/@trimjs/web-app) 与 [0.5.0 发布包](https://registry.npmjs.org/@trimjs/web-app/-/web-app-0.5.0.tgz)：核对 README、类型及桥接实现。下载到临时目录检查即可，不安装其脚本；不要将依赖缓存打包进技能。

SDK 0.5.0 可支撑就绪机制、传输 envelope 以及 README 对手机 `getUserMessage` 的提及；不能支撑该方法必然返回某组凭据字段。`getSessionCredentials()` 的 Desktop 示例不属于手机 payload 定义。

## 项目观察，不能提升为平台保证

本技能提炼自一个经统一网关运行的 Web 应用认证适配，未复制项目部署配置、私有链接、账号或相册标识。以下结论保留其适用边界：

- Android App `1.37.3` 的一次设备诊断确认桥已就绪，但 `getUserMessage` 原始返回 `null`。这不是“只要是 Android 就返回空值”的规律。
- 目标 NAS 自带 Docker 前端观察到读取 `fnos-Secret`、`fnos-token` Cookie。由此形成仅原生原始空返回时的兼容路径，不保证每台 NAS 或每个手机宿主都注入 Cookie。
- 目标网页宿主观察到 localStorage 会话，统一网关观察到系统 Cookie 不转发给应用后端。只在重新核对的部署环境应用这些结论。
- 目标相册前端/上传 worker 观察到 JSON API 的 `authx` 与上传的 `Trim-Sign`、可选 `Trim-Token` 分工。这些是内部服务协议，系统升级后需重新验证。
- 目标 `/app/token` 成功为空体；相册无效签名曾返回业务 5000，业务 403 具有权限类语义。不同接口或版本可能不同，不能泛化错误码。
- Android Cookie 兼容版曾被用户确认测试成功；后来 iOS 测试也被用户确认通过并恢复正式页面。iOS 早先业务 403 的根因未独立确定，不能声称已经证明是 Cookie 注入、账号不一致、签名或相册 ACL 引起。
- 同源父页面桥、5 秒超时、固定包装解析、诊断阶段等是兼容实现选择。设备反馈通过不能证明所有兼容分支都被实际执行。

本技能不要求访问来源项目或某台 NAS。目标任务需要内部协议证据时，在用户已授权的环境中只读检查相应发布包或前端；仅保留版本、逻辑摘要和脱敏测试结果。未经核对的新 handler、字段别名和参数不写入实施方案。

## 修改会话模块时的回归覆盖

使用固定合成凭据，禁止录制真实凭据作为 fixture。按改动风险选择相关项目已有测试工具，不为文档改动要求运行整个来源项目。

### 解析与来源

- 对象、JSON envelope、嵌套 `result`、已确认的 `data` 包装，可选 token 缺省。
- 非零 code、数组、畸形/超长 JSON、非法 Base64、空 secret、非法或超长 token 被拒绝。
- 原生结果优先于旧网页存储；不从 Cookie 补齐有效原生结果的 token。
- 仅原始 null/undefined 进入 Cookie 分支；字符串 `"null"`、拒绝、超时、非空格式错误、缺桥不进入。
- Cookie 解码一次，同名多值、错误编码、不可读和缺失各自可诊断；手机不读 localStorage。

### 异步与框架

- 桥延迟注入、事件先于订阅、已就绪标记、Apple 已有桥、其他平台未就绪。
- 同源父桥与当前窗口分别记就绪；跨源父页不访问凭据、不发送会话消息。
- 预先取消、等待期间取消、调用后取消、超时后迟到返回；每次获取至多一次原生调用。
- 结束后没有残余轮询和临时监听，取消或超时后不继续网络写入。

### 请求与诊断

- 请求固定同源，Cookie 交给浏览器；跨源地址、异常重定向不能携带上传材料。
- 若涉及上传，验证实际发送路径与签名文本一致，secret 不进入业务 API，token 仅进入指定上传请求。
- HTTP 状态与业务码分别记录，阶段切换不会保留上一步的成功码。
- 用含合成秘密的原始字符串、错误文本、未知对象 key、用户字段和 URL 触发失败，断言诊断和复制内容均不含这些值。
- 手动会话诊断不发业务写请求；失败不自动重试上传或分享。

## 设备验收和结论

先记录目标系统、App、SDK 与应用构建版本及访问环境，再检查实际安装的微应用声明是否生效。真实设备不得注入假的桥或 Cookie 后声称验证宿主能力。

按实际支持的访问环境分别验证：网页宿主、Android App、iOS App；内网访问和远程网关不能互相替代。每种环境分别给出：

1. 桥/会话检查结果：来源、固定阶段、仅格式校验还是服务端接受。
2. 已授权业务结果：是否完成目标操作，使用哪个固定阶段确认，若失败提供 HTTP/业务码。
3. 验证性质：单元模拟、浏览器环境模拟、真实设备，或用户明确反馈。

需要核验账号切换、会话过期和多用户权限时，在已有授权与可用测试账号内完成；没有条件则列为未验证，不变更生产 ACL 来制造成功。

模拟测试只能证明所写逻辑处理了对应输入。来源项目历史设备反馈不代替新项目验收。结论应精确到“此版本此环境的操作通过”，不得扩写为“所有飞牛认证已解决”。

## 技能自身的使用验证

维护本技能时至少检查以下典型需求是否能定位到操作步骤和输出：

- “Android 飞牛 App 桥就绪但返回 null”：走原始空值判断和有证据的 Cookie 兼容，缺少材料时输出 `FNS_NATIVE_EMPTY`，不猜字段。
- “iOS 上传提示 403”：保留会话来源并定位具体端点阶段，区分 HTTP 和业务码，不直接修改相册权限。
- “应用服务端调用官方平台配置 API”：选择应用 token 与 Unix Socket，不读取手机桥或向前端传 token。

检查 frontmatter 名称与目录一致、全部相对引用存在、无私有地址和凭据、入口说明了参考文件的读取时机。技能安装到目标 Agent 后再验证发现/触发能力；仅文件校验不能声称平台集成测试通过。
