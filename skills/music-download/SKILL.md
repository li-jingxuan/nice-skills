# 下载歌曲并入库

用中文交互。识别歌名、歌手、指定的专辑或版本、音质以及 NAS 目录。仅要求搜索下载来源时，用 `search` 展示候选。处理用户有权下载的音频。命令用法见 [执行参考](references/runtime.md)。

## 查音乐库

问「下载过吗」「库里有吗」或要求下载时，先用 `lookup` 在整个 `MUSIC_LIBRARY_ROOT` 的 SQLite 索引中查询。传基础歌名，已知歌手时一并传入。首次查询自动建库。用户要求刷新时运行 `reindex` 并报告已索引的文件数。

- 用户指定目录并要求将歌曲写入索引时，用 `scan --directory …` 递归扫描。目录必须位于 `MUSIC_LIBRARY_ROOT` 内。汇报新增、更新及已存在的记录数。重扫同一路径只保留一条记录，不同路径的同名音频各自保留。
- 仅查询时报告匹配文件的歌手、版本、格式和路径。未指定格式时展示库中已有的格式。无有效命中时说「音乐库索引里没查到」。查询出错时说明无法确认是否已入库。缺少 `MUSIC_LIBRARY_ROOT` 时按下方说明引导配置。
- 要下载时，根据歌手、版本、明确指定的专辑及格式判断。没有指定格式时使用 FLAC。仅给出歌名时，查到同名文件也按下方规则确认演唱者和版本，再判断是否已入库。已有不同格式的同一版本时，先告知，再继续找目标格式。
- 下载前查到符合要求的文件时跳过网盘操作。能确定一个目标文件时用 `lyrics --path …` 补歌词，再回报「已入库」及路径。用户明确指定了目录时，先用 `destination --directory …` 解析路径。匹配文件都在其他目录时，告知现有路径，问是否也需要在指定目录存一份。用户确认后，沿用已确认的版本、格式和目录继续。
- 用户未指定的歌手、版本或专辑经选曲才确定时，在进入 `detail` 或 `share` 前用这些信息重新判断是否已入库。文件名索引未提供专辑或版本时，根据已有信息列为候选。用户明确指定专辑或版本时，仅在对应信息能确认匹配的情况下跳过下载。默认 FLAC 找不到符合要求的来源时，自动按同一首歌、歌手和版本寻找 MP3。用户加 `--flac-only` 时保留无损要求并记录无来源。

## 保存目录

需要实际下载时运行 `destination` 检查保存目录。用户指定了目录就带上 `--directory`。默认目录应位于已配置的音乐库根目录内。

- 缺少可用的 `MUSIC_LIBRARY_ROOT` 时，提示「请先配置 NAS 音乐库。例如把 `MUSIC_LIBRARY_ROOT` 设为 `/music`，把 `MUSIC_LIBRARY_DEFAULT_DIR` 设为 `/music/华语`。请换成 OpenClaw 能访问的实际挂载路径。」保留本次歌曲请求，配置后继续。
- 只有默认目录需要配置且用户没指定本次目录时，提示「你想把歌保存到哪个目录？这次可以直接告诉我路径。以后想省略目录，可以在 OpenClaw 设置 `MUSIC_LIBRARY_DEFAULT_DIR=/music/华语`。」等用户给出本次目录或完成配置后继续。
- 本次指定目录可用且 `default_configured` 为 `false` 时，继续下载，并在本次会话首次遇到该状态时顺带提示如何设置默认目录。默认目录已配置且本次检查通过时直接继续。
- 本次指定目录无效时，根据 `message` 说明原因，等用户改用有效目录后继续。

## 下载流程

1. 普通单曲用 `resolve-source --title … --artist …` 自动选源，可加 `--album`、`--version`、`--format` 应用用户明确指定的条件。它共用批量匹配器，会查库并通过 `search`、`detail` 和 `share` 核对条目和实际文件。仅给歌名时尝试用正式发行信息核实演唱者。用户已指定分享文件时直接沿用。
2. 确认候选中有完整歌名和指定歌手的署名，即可在 **夸克 FLAC → 夸克 MP3 → 百度 FLAC → 百度 MP3** 的顺序中自动选第一份可用来源。合唱署名包含所需歌手也可匹配。同一档优先选歌名和歌手完全匹配的条目，分享内优先选文件名带歌手的音频。未指定专辑时，同一首歌分布在多个专辑或合集里可以直接选。默认排除明确标注的翻唱、现场、DJ、重混和伴奏。指定格式时只查该格式。
3. `selected` 时直接下载。`already_in_library` 时按返回路径复用现有文件。`needs_review` 时先用 `search`、`detail` 和 `share` 补查歌手、版本或分享目录。能核实时直接选源，仍有歧义时才列出带编号的候选，说明待核对的字段，保留候选 ID 和分享位置供续接。
4. 用 `download` 将选中的单个音频转存并下载。传入 `file` 的 `url`、`file_fid`、`page` 及子目录参数，`file_format` 对应 `--format`，`resolved` 提供歌名、歌手、专辑和版本。夸克子目录用 `--folder-fid`，百度用 `--source-dir`。脚本校验音频，发布到 NAS，写入索引并尝试保存同名 LRC。
5. `download` 返回 `saved` 或 `exists` 后，回复歌手、歌名、实际格式、最终路径和歌词结果。`index_warning` 表示文件已入库，索引待刷新。失败时报告环节并保留已有暂存信息。链接需要提取码时向用户索取。授权失败时通过对应网盘的官方流程恢复授权，百度使用官方 `baidu-drive` Skill。百度返回 `waiting_transfer` 时说明转存结果待核对，保留 `baidu_staging.path` 和已有的 `task_id`，稍后使用 `--staging-dir` 续接。
6. 音频校验并保存到 NAS 后，脚本自动删除此次百度网盘的暂存音频。`staging_cleanup.status` 为 `removed` 表示该副本已清理。若为 `manual` 或 `warning`，告知用户暂存位置和原因。夸克官方 CLI 暂无删除命令，可在夸克客户端将对应副本移入回收站。

## FLAC 超过下载上限

- 夸克 FLAC 返回 `error_code: download_size_limit` 时，跳过超限文件并继续查符合条件的夸克 FLAC。夸克没有可用 FLAC 且允许使用 MP3 时，依次查夸克 MP3、百度 FLAC、百度 MP3。夸克的字节上限只用于筛选夸克文件。
- 切换网盘或格式时，沿用原保存目录，并使用所选文件自己的链接、文件 ID、页码、目录及提取码。
- 用户要求只要无损时，完成两家 FLAC 来源的核对后报告结果。存在版本歧义时列出候选。成功时报告实际网盘、格式、音频和歌词路径。

## 批量下载

1. 从用户本次直接提供的歌曲创建 UTF-8 清单，一行一首，支持 `歌名` 或 `歌手 - 歌名`。需要保留专辑或版本时用 JSON 曲目数组。普通清单用 `batch-add --input`。下载酷狗歌单时，用 `tracks --for-download` 获取临时清单，将 `manifest_path` 传给 `batch-add --consume-manifest`。部分读取时说明缺口，用户确认后加 `--allow-partial`。沿用本次目录和格式要求，只要无损时加 `--flac-only`。批次提交后自动清理临时清单，看到 `manifest_cleanup_warning` 时可用原参数重试清理。
2. 用 `batch-run --job …` 启动批次。默认最多 10 首并发，一首结束就补下一首。逐首查库后，已入库的记录路径，能确认原唱或指定版本的自动下载。每首失败后独立重试最多 5 次。确认没有匹配音源时记为 `no_source`，其余曲目继续。批次较长时用后台命令执行，通过 `batch-status --job …` 查看进度。
3. 批量和单曲共用相同的网盘和音质优先级。集中展示 `needs_review` 曲目的歌源和无法确认的信息，批次会继续处理其他曲目，结束后按编号给出确认表。待确认曲目达到 10 首时提前暂停并先确认。用户说继续后，用 `batch-run --job … --continue-review` 处理剩余队列。用户按编号选择后用 `batch-select --job … --item … --track-id …` 排回队列，指定分享文件时一并传原链接和文件位置。授权或 NAS 等共用环境异常时报告暂停原因。环境恢复或任务中断后，用原批次 ID 继续 `batch-run`。
4. 报告已下载、已在库、清单内重复、待确认、无音源、失败和待处理的数量。若有暂存副本待手动处理，汇报位置和原因。百度 `waiting_transfer` 记录继续核对所需的暂存信息，其他曲目可继续。稍后用原批次 ID 续跑。失败和无音源曲目分别查询，对失败条目保留最后阶段、原因和历次重试记录。用 `batch-status` 的分页参数按需查看详细列表。

## 匹配时间轴歌词

- 给已有音频补歌词时，用用户给出的库内路径，或先用 `lookup` 确定目标文件，再执行 `lyrics --path …`。可以用 `--title`、`--artist`、`--album`、`--version` 补充已确认但音频标签缺失的信息。只问歌曲是否在库时，查库即可。
- 歌词查询依次使用 LRCLIB、网易云音乐、QQ 音乐和酷狗音乐。接口使用匿名请求，遇到限流或暂时不可用时尝试下一家。只保存含逐行时间戳的歌词。`saved` 或 `exists` 时回报同目录的 `.lrc` 路径。已有侧车文件和原音频均保留。
- 中文歌词在同等可信度下优先选择简体版。先找到繁体或字形不明确的版本时继续补查，找不到符合条件的简体版就沿用匹配的歌词。英文歌词沿用默认匹配顺序和原文。
- `needs_review` 时显示候选的来源、歌名、歌手、专辑和时长，缺失字段标为「未标注」。同曲目下有不同的时间轴时也需要确认。用户选择后，对同一个音频路径用 `lyrics --source … --id …` 保存对应歌词，沿用原请求中已确认的元数据。
- `not_found` 时说明没有匹配的时间轴歌词。`unavailable` 时说明哪些来源暂时不可用。`error` 时报告歌词步骤的错误。音频成功入库后，补歌词可独立重试。
